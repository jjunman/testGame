# 프로젝트 공부 계획서

## 1. 공부 목표

이 프로젝트를 공부하는 목표는 코드를 전부 외우는 것이 아니다.

목표는 다음과 같다.

- 내 프로젝트가 어떤 기술들로 이루어졌는지 설명할 수 있다.
- 사용자가 앱에서 버튼을 누르면 코드가 어떤 순서로 움직이는지 설명할 수 있다.
- 모바일 앱, 서버, DB가 각각 무슨 역할을 하는지 구분할 수 있다.
- 내가 아는 부분과 모르는 부분을 문서로 정리하면서 공부한다.

## 2. 현재 내 실력 객관화

현재 기준으로 내 실력은 다음과 같이 본다.

| 분야 | 현재 상태 |
| --- | --- |
| HTML | 기초 있음 |
| CSS | 기초 있음 |
| JavaScript | 기초 있음 |
| TypeScript | 입문 단계 |
| Python | 기초 있음 |
| React Native / Expo | 거의 처음 |
| 백엔드 서버 | 거의 처음 |
| DB | 거의 처음 |
| 전체 앱 구조 이해 | 이제 시작 |

중요한 것은 "못한다"가 아니라, 어디부터 모르는지 정확히 아는 것이다.

## 3. 이 프로젝트의 큰 구조

이 프로젝트는 모노레포 구조다.

모노레포는 여러 개의 앱과 패키지를 하나의 프로젝트 폴더 안에서 같이 관리하는 방식이다.

```text
testGame/
  apps/
    mobile/          # Expo React Native 모바일 앱
    server/          # NestJS 백엔드 서버
  packages/
    shared-types/    # 모바일 앱과 서버가 같이 쓰는 타입
  docs/              # 공부 문서와 프로젝트 설명
  package.json       # 전체 프로젝트 명령어와 workspace 설정
```

각 폴더의 역할은 다음과 같다.

- `apps/mobile`: 사용자가 직접 보는 모바일 앱 화면
- `apps/server`: 앱에서 보낸 요청을 처리하는 서버
- `packages/shared-types`: 앱과 서버가 함께 쓰는 TypeScript 타입
- `docs`: 프로젝트 설명, 공부 노트, 구조 정리 문서

## 4. 공부 카테고리와 우선순위

### 1순위: 프로젝트 전체 지도

먼저 전체 구조를 이해한다.

공부할 내용:

- 모노레포가 무엇인지
- `apps/mobile`, `apps/server`, `packages/shared-types`가 각각 무엇을 하는지
- 모바일 앱과 서버가 어떻게 대화하는지
- 사용자가 보는 화면과 서버 코드가 어떻게 연결되는지

이 부분을 모르면 기능별 코드를 볼 때 길을 잃기 쉽다.

### 2순위: TypeScript 기초

JavaScript를 알고 있다면 TypeScript는 "JavaScript에 설명서를 붙이는 것"처럼 보면 된다.

공부할 내용:

- `type`
- `interface`
- 함수 매개변수 타입
- 배열과 객체 타입
- `Promise`
- `async / await`

### 3순위: React Native / Expo 기본

모바일 앱 화면을 이해하기 위해 필요하다.

공부할 내용:

- Component
- props
- `useState`
- `useEffect`
- 화면 이동 Navigation
- 버튼을 눌렀을 때 함수가 실행되는 흐름

### 4순위: 모바일 앱 구조

앱 쪽 파일들이 어떤 역할을 하는지 공부한다.

주요 파일과 폴더:

- `apps/mobile/src/App.tsx`
- `apps/mobile/src/navigation/AppNavigator.tsx`
- `apps/mobile/src/screens`
- `apps/mobile/src/components`
- `apps/mobile/src/store`
- `apps/mobile/src/api/client.ts`

### 5순위: 서버 기본 구조, NestJS

서버가 요청을 어떻게 받는지 공부한다.

공부할 내용:

- Controller: 요청을 받는 곳
- Service: 실제 로직을 처리하는 곳
- Module: 기능을 묶는 곳
- DTO: 요청과 응답 데이터의 모양
- Entity: DB 테이블의 모양

### 6순위: DB / TypeORM

데이터가 어떻게 저장되는지 공부한다.

공부할 내용:

- User, Band, Song, Practice 같은 데이터 구조
- `*.entity.ts` 파일 읽기
- 유저와 밴드의 관계
- 밴드와 멤버의 관계
- 곡 후보, 투표, 연습 과제의 관계

### 7순위: 기능별 깊게 보기

기초 구조를 본 뒤 기능별로 나누어 공부한다.

기능 목록:

- 로그인 / 회원가입
- 밴드 만들기 / 초대코드로 가입
- 곡 투표
- 개인 연습
- 일정 조율
- 합주실 후보
- 정산

### 8순위: 배포 / 실행 환경

마지막에 공부해도 된다.

공부할 내용:

- `package.json`
- `.env`
- Expo 실행
- PostgreSQL
- Railway 배포

## 6. 채팅방 나누기 추천

공부할 때는 채팅방을 기능별로 나누는 것이 좋다.

추천 채팅방:

```text
[공부 1] 전체 구조
[공부 2] TypeScript 기초
[공부 3] 모바일 앱 구조
[공부 4] 로그인 / 회원가입
[공부 5] 밴드 만들기 / 가입
[공부 6] 서버와 DB
[공부 7] 곡 투표
[공부 8] 개인 연습
[공부 9] 일정 / 합주실 / 정산
[공부 10] 전체 발표 / 포트폴리오 정리
```

첫 번째 채팅방에서는 이렇게 시작하면 좋다.

```text
나는 중3이고 HTML/CSS/JS는 알고 TypeScript는 조금 알아.
이 프로젝트를 처음부터 공부하려고 해.
먼저 전체 구조를 초보자 기준으로 설명해줘.
파일 경로를 보여주면서, 모바일 앱/서버/DB가 어떻게 연결되는지 알려줘.
그리고 마지막에 내가 정리할 수 있는 공부 노트 형식도 만들어줘.
```

## 7. 공부 노트 양식

각 기능을 공부할 때는 아래 양식으로 정리한다.

```md
# 공부 주제: 밴드 만들기

## 1. 이 기능이 하는 일

사용자가 밴드 이름과 포지션을 입력해서 새 밴드를 만든다.

## 2. 관련 화면

- CreateBandScreen.tsx
- BandListScreen.tsx

## 3. 관련 서버 코드

- bands.controller.ts
- bands.service.ts
- band.entity.ts
- band-member.entity.ts

## 4. 사용자가 누르면 일어나는 흐름

1. 앱에서 밴드 만들기 버튼을 누른다.
2. 입력값을 확인한다.
3. 서버에 POST 요청을 보낸다.
4. 서버가 DB에 밴드를 저장한다.
5. 앱이 밴드 목록으로 돌아온다.

## 5. 오늘 새로 알게 된 것

- Controller는 요청을 받는 곳이다.
- Service는 실제 로직을 처리하는 곳이다.

## 6. 아직 모르는 것

- TypeORM 관계 설정
- JWT 인증 방식
```

## 8. 공부할 때의 기준

공부할 때는 다음 질문에 답할 수 있으면 된다.

- 이 파일은 무슨 역할인가?
- 이 화면에서 사용자가 누르면 어떤 함수가 실행되는가?
- 앱은 서버에 어떤 요청을 보내는가?
- 서버는 요청을 받으면 어떤 Service를 실행하는가?
- DB에는 어떤 데이터가 저장되는가?
- 이 기능을 내가 말로 설명할 수 있는가?

처음부터 완벽하게 이해하려고 하지 않는다.

먼저 큰 흐름을 잡고, 그다음 파일을 하나씩 읽는다.
